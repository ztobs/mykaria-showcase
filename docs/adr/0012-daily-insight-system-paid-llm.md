# 0012: Daily Insight Generated with System-Paid LLM

## Status

Accepted (2026-07-28)

## Context

The dashboard gains a daily AI-generated tip ("Daily Insight") that summarizes each user's application patterns — velocity, response rate, funnel drop-off, source effectiveness — and suggests one actionable improvement. Every other LLM feature in the app resolves the *user's own* provider key first and falls back to the system key, meaning users largely pay their own LLM costs. A scheduled, server-side tip has no user request context, so a key owner had to be chosen deliberately. Cost exposure needed bounding: generating a tip for every registered user daily would be wasteful given the share of dormant accounts.

## Decision

The Daily Insight is generated by the daily cron job (`dailyInsightGeneration`, 06:00 UTC) using the **system/global LLM provider key** — the platform pays, for **all tiers including free**. Cost is bounded by an eligibility filter: a user receives a tip only if they have **≥ 3 applications** and **activity (application created or status changed) within the last 7 days**. Tips are stored in the `DailyInsight` table with a `@@unique([userId, date])` constraint so re-runs are idempotent. LLM failure is silent — no tip row is written, the dashboard shows nothing, no error surfaces. The tip is written in the user's stored locale preference (falling back to English) and covers application *patterns* only, never CV or cover letter content.

## Alternatives considered

- **Rule-based insight engine (no LLM)** — deterministic template tips picked from stats. Zero cost and fully reliable, but generic and noticeably less valuable; rejected because the personal, natural-language quality of the tip is the point of the feature.
- **Hybrid: LLM only for users with their own key configured, rule-based otherwise** — eliminates platform cost entirely, but makes the feature inconsistent across users and punishes exactly the (free-tier) users least likely to configure a key; rejected on product grounds.
- **Tier-gating the LLM tip to paid plans** — rejected for launch; the eligibility filter already caps cost to active users. Gating remains a one-line config change in `tier-limits.js` if cost becomes a problem.

## Consequences

- Easier: every active user gets the feature; no key-resolution edge cases; strong retention/delight signal for free users.
- Harder: recurring platform LLM cost that scales with active-user count; the eligibility window (7 days) and model choice (cheapest configured system model) are the tuning knobs. `DailyInsight` rows older than 30 days are purged by the existing data-retention cron.
